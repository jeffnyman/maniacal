# Maniacal roadmap

What is done, what comes next, and where each piece comes from. Source references are to the
ScummVM checkout next to this repository (`scummvm/engines/scumm`); `docs/...` is the documentation
in this repository; [docs/building-an-interpreter.md](docs/building-an-interpreter.md) explains the layers below.

## Design

ScummVM builds Maniac Mansion's engine as a chain of subclasses:
`ScummEngine_v0 : v2 : v3old : v3 : v4 : v5 : ScummEngine`. Much of what Maniac Mansion runs on
lives in the V5 and base classes, mixed with code for later games (iMUSE, HE, SMUSH, AKOS,
256 colours). Maniacal does not port that chain. It has one flat `ScummEngine` with the version (0, 1
or 2) as data, and it takes from each ScummVM function only the branches that `_game.version <= 2`
and `GID_MANIAC` reach. Where V0 genuinely differs (scripts, verbs, actor walking), it gets its own
class, as Daventry did for preAGI.

The three versions split the work like this:

| | V0 (C64) | V1 (DOS 1987) | V2 (DOS 1988) |
|---|---|---|---|
| Scripts | `script_v0.cpp` | `script_v2.cpp` | `script_v2.cpp` |
| Index | inside the disk image | `readClassicIndexFile` | `readEnhancedIndexFile` |
| Room graphics | `GdiV1` (C64 character tiles) | `GdiV1` | `GdiV2` |
| Costumes | `V0CostumeLoader` / `V0CostumeRenderer` | `ClassicCostume*`, version 1 branches | `ClassicCostume*` |
| Sound | `Player_SID` | `Player_V1` (PC speaker, PCjr) | `Player_V2` (PC speaker, PCjr) |
| Verbs | V0 sentence UI (`ScummEngine_v0::checkExecVerbs`) | V2 verbs | V2 verbs |

So the order is V2 first, because ScummVM's support for it is the best exercised and it has the
fewest special cases. V1 follows by swapping in the `GdiV1` graphics and V1 costumes under the same
script VM. V0 comes last, with its own scripts and verbs, which then reuse V1's graphics.

Every phase ends with a headless check, as in Daventry: a screenshot of a known room, or a scripted
run of clicks that reaches a known state.

## Done

- Solution layout on the Daventry host packages (`Daventry.Core`, `Daventry.Audio`, `Daventry.Host.Sdl`).
- Detection: ScummVM's 40 Maniac Mansion MD5 rows (generated by `tools/port_md5_table.py`), the
  variant-to-version table of `detection_tables.h`, and identification of the loose-file releases by
  `00.LFL` / `00.MAN`. V1 and V2 English DOS are identified.
- Resources (V1 and V2): the XOR-encoded `.LFL` files (`LflFile`), both index formats
  (`ResourceIndex`: object owners and states, and where every room, costume, script and sound
  is), and loading a resource by its size word (`ResourceLoader`). Checked against both releases:
  every room file is a chain of sized resources, and the index entries that point at real resources
  are counted and pinned in the tests.

## Phase 1: resources (done)

Both DOS releases, in `Maniacal.Scumm.Resources`, `Rooms`, `Graphics` and `Costumes`:

- `file.cpp`, `resource.cpp`, `resource_v2.cpp`: the XOR-encoded LFL files, both index formats, and
  loading a resource by its size word (`ResourceLoader`).
- `room.cpp`, `object.cpp`, `boxes.cpp` (reading): the room header, the objects' code blocks
  (number, geometry, parent, walk-to point, preposition, name, verb table), the walkboxes and box
  matrix, the entry and exit scripts, and the sounds and scripts loaded with each room.
- `gfx.cpp`, `palette.cpp`: room pictures and masks (`V2Bitmap`, `V1Bitmap`), object images, and
  drawing a room with its objects as `drawRoomObjects` does (`RoomRenderer`), in EGA colours.
- `costume.cpp`: the classic costume format (`0x58`, V2) and its C64-derived variant (`0x57`, V1):
  animations, limb command runs, cels, and figures built from them (`Costume`, `CostumeRenderer`),
  with V2's start offset of (-72, -100) from `drawCostume` and V1's actor colour tables.
- No charset files: V1 and V2 fonts are built into the engine (`ScummEngine_v2::loadCharset` is a
  stub); the font is ported in Phase 2.
- `maniacal <folder> --room N [--objects none|initial|all] [--mask]` and
  `maniacal <folder> --costume N` write rooms and costume sheets as PNGs (`--zoom N` to enlarge).
- Checked: every room, object image and costume of both releases decodes; pictures match the room
  maps by eye and an independent decoder by hash; the room layouts end exactly where the next part
  begins.

## Phase 2: drawing (V2, then V1)

- Done: the V2 picture and mask decoder (`GdiV2::prepareDrawBitmap`, `generateStripTable`) as
  `V2Bitmap`, and the EGA palette. Every V2 room decodes, ending exactly where its object images begin.
- Done: the V1 tile decoder (`GdiV1::roomChanged`, `decodeV1Gfx`, `drawStripV1Background`,
  `drawStripV1Mask`) as `V1Bitmap`, with the Maniac Mansion EGA row of `setV1ColorTable`. Every V1
  room decodes, ending exactly where its object images begin.
- The CGA and Hercules colour maps of `setV1ColorTable` and `resetPalette`, if wanted.
- `palette.cpp`: done for DOS; V1 and V2 both use the EGA palette (`resetPalette`). The C64 palette
  comes with V0.
- Done: actors on the room (`RoomView`): the position offsets of `Actor_v2::prepareDrawActorCostume`
  (+8 in V2, +16 facing left), V1's one-line drop, and clipping by the room mask when the actor's
  walkbox has one (ScummVM's two mask planes: plane 0 empty, plane 1 the room's). Still to do: the
  dark-room colours of `setPalette`, and sorting actors by depth (with the walking code).
- Done: the built-in English font (`CharsetRendererV2`, `charset-fontdata.cpp`, generated by
  `tools/port_fonts.py`), with V1's own apostrophe, and drawing text with it (`Font`). Other languages'
  replacement glyphs can be ported the same way when there is data to test them.
- Done: `camera.cpp` (`Camera`): the view centre in pixels, 8 pixels a step, following an actor past
  view columns 10 and 30, panning, and the script limits that `startScene` resets on each room.
- Done: the screen layout of `initScreens` (`ScreenLayout`), and
  `maniacal <folder> --view N [--camera X] [--actor costume,x,y[,direction]]...`, which writes the
  320x200 screen with the room and standing actors.
- `gfx.cpp`: drawing into a 320x200 frame each step with dirty strips, for the engine loop.
- Check: headless screenshots of rooms with actors in them, matching ScummVM's output.

## Phase 3: the interpreter (V2 and V1)

- Done: decoding (`Maniacal.Scumm.Scripts`): the opcode table of `ScummEngine_v2::setupOpcodes`
  (generated by `tools/port_opcodes.py`) and the operand layout of each of its 107 handlers
  (`ScriptDecoder`), with decoding along every path execution can take. Every global, room and
  object script of both releases decodes, with jumps landing on instruction boundaries; the only
  leftover bytes are 20 after V2 script 59. `maniacal <folder> --script N` and `--room-scripts N`
  print the disassembly.
- Done: the script engine core (`ScriptEngine`): 80 slots, nested starts, `runAllScripts`, delays,
  freezing, the user state, cutscenes and overrides, variables (with the 14-16 redirection and the
  exit-key remap), bit variables, object states and owners, and the variable, arithmetic,
  condition, jump and script-control instructions. Every other instruction goes to an
  `IScriptHost` with its operands evaluated. `maniacal <folder> --run [steps]` runs the boot script
  headless and lists what the scripts asked of the world: both releases reach the kid selection.
- Done: the first world host (`GameWorld`): `loadRoom` as `startScene` does it for these versions
  (leave and kill the room's scripts, the exit script, the room variable, the camera limits, the entry
  script, then script 5), `setCameraAt`, `panCameraTo`, the camera limits of `roomOps`, and `lights`;
  a main-loop step (delays, scripts, camera); and the screen drawn from the object states.
  `maniacal <folder> --run [steps] --screenshot file.png` shows the title screen in both releases.
- Done: actors without walking (`Actor`, `CostumeState`): the per-limb costume state of
  `costumeDecodeData` and `increaseAnim`; `putActor`, `showActor`, `hideActor`, `setActorCostume`,
  `animateActor`, `setDirection` and `animateCostume`; V1's default costumes and talk colours;
  `actorOps`, the put and query instructions, `actorFollowCamera` and `loadRoomWithEgo`; drawing
  the actors in the room back to front, in their palette under the current lights. With the kid
  selection stood in for by `--set` and the intro skipped by `--skip`, both releases reach the start
  of the game with the three kids on the driveway.
- Done: walking (`BoxGeometry`, `Actor`): the box geometry of `boxes.cpp`, V2's
  `adjustXYToBeInBox` and `adjustActorPos`, `startWalkActor`, `walkActor` leg by leg through the box
  matrix, `calcMovementFactor` and `actorWalkStep`, turning a quarter at a time
  (`updateActorDirection`, `remapDirection`), and the box flags `setBoxFlags` changes. The walk,
  face, wait and distance instructions; `drawObject` without moving; and the per-step engine
  variables of `scummLoop_updateScummVars` (the camera column). The intro plays through in both
  releases, from the meteor to the kids on the driveway.
- Done: text (`MessageLine`): `decodeParseString`, `convertMessageToString` (numbers, verb and
  object names, text in variables), `actorTalk`, `displayDialog` with its wrap, new-line, wait and
  keep escapes, the talk delay of 60 ticks and 6 a character, `stopTalk` and the talk frames;
  `print`, `printEgo` and `waitForMessage`; and the main loop's tick count and message variable.
  The intro's text and the kids' first lines show on the message line in both releases.
- Done: verbs, the sentence and input (`VerbArea`, `GameWorld.Interface`): `o2_verbOps`,
  `drawVerb`, `redrawVerbs`, `verbMouseOver` and `findVerbAtPos`; the sentence queue of
  `o2_doSentence`, `checkAndRunSentenceScript`, `waitForSentence` and `drawSentence` with
  prepositions; the inventory (`pickupObject`, `setOwnerOf`, `redrawV2Inventory`, its scrolling and
  highlight boxes); `findObject`, `actorFromPos` and `getObjPreposition`; `processInput` and
  `ScummEngine_v2::checkExecVerbs` with the input script, the verb and inventory keys, and Escape,
  F4 or the right button for skipping cutscenes; the end of a cutscene giving the camera back to
  the kid; and the V2 crosshair cursor. `ScummEngine` runs it all on a Daventry host, a step every
  `VAR_TIMER_NEXT` sixtieths of a second. Both releases play from the title through the kid
  selection (by clicking) and the intro to the driveway, out to the front of the house, and the
  key under the door mat goes into the inventory, headless and in the SDL window.
- Done: objects and lights: `o2_drawObject` moving an object and its walk-to point for as long as
  the room is loaded, `setObjectName` and the new names `getObjOrActorName` gives first,
  `getClosestObjActor`, and dark rooms: black where the room lights are off (`clear8Col`), with
  the flashlight of `o2_lights` and `drawFlashlight`, its corners rounded by the version 1 and 2
  curves, lighting the room around the mouse. Rooms 5, 8, 9, 15, 22 and 23 start dark.
- Done: into the house, checked against ScummVM 2.7.0 by loading the same saves in both: the hall,
  the kitchen, Edna catching a kid and locking him in the dungeon, the dungeon's brick and door, the
  gargoyle that holds a door open while the kid who pulled it stands still, and the basement dark
  and lit. Every opcode the game's scripts use has a handler. Two fixes came of it: a load from
  outside the save screen now goes through the save room inside a cutscene and back, as ScummVM's
  does after a launcher load (`ScummEngine_v3::scummLoop_handleSaveLoad`, with
  `terminateSaveMenuScript` for a save made in the save room), which puts the camera on the kid;
  and `o2_restart` starts the game over (`ScummEngine::restart`).
- Where ScummVM 2.7.0 and the current ScummVM differ, Maniacal follows the current one: after a
  user state change the sentence line is drawn again (`runInventoryScriptEx`), and only version 1
  puts back the camera mode a cutscene began with (`o2_endCutscene`).
- Next: Phase 5 (the C64).
- `script.cpp`: script slots, `runScript`, `runObjectScript`, `runEntryScript`/`runExitScript`,
  cutscenes, `stopScript`, freeze and unfreeze, the bit variables.
- `script_v2.cpp`: the V2 opcode table (also used by V1) and every handler.
- `vars.cpp`: `ScummEngine_v2::setupScummVars` and `resetScummVars`.
- `scumm.cpp`: the main loop (`scummLoop` and what it calls each frame), `resetScumm`, timing.
- `actor.cpp`: `Actor`, `Actor_v3` and `Actor_v2`, with walking, facing, animation and talking.
- `boxes.cpp`: walkboxes, the box matrix and path finding, version 2 branches.
- `verbs.cpp`: `initV2MouseOver`, `checkV2MouseOver`, `redrawV2Inventory`, `checkExecVerbs`.
- `string.cpp`: messages, `drawSentence`, talk text.
- `input.cpp`: mouse and keyboard, `ScummEngine_v2::processKeyboard`.
- Cross-check script behaviour against `docs/scripts`. Those are the C64 scripts: the logic is
  the same game, but DOS renumbers scripts, variables and objects (see
  `docs/scripts/README.md`, "The DOS releases"), so build a V0-to-DOS number map before naming
  variables from the tables in debug output.
- Check: from the title, through the intro and kid selection, to walking around the front of the
  house, headless and in the SDL window.

## Phase 4: sound, saves and options (V2 and V1)

- Done: sound (`Maniacal.Scumm.Sound`): `Player_V2Base` and `Player_V2`, the four-channel
  sequencer of version 2 with its hulls and modulation curves (tables generated by
  `tools/port_sound_tables.py`); `Player_V1`, the chunked effects of version 1; the PC speaker's
  and PCjr's synthesis, the PCjr by default as ScummVM chooses it (`--speaker` for the other);
  the queue of `sound.cpp` with `startSound`, `startMusic`, `stopSound`, `stopMusic`,
  `isSoundRunning`, `VAR_LAST_SOUND` and the music timer. With it, the main loop's clock is the
  original's: steps last `VAR_TIMER_NEXT` ticks of 4 quarter-frames at 1193182 / 5041 Hz in
  version 2, and in version 1 a multiple of 3 ticks at 12 quarter-frames a tick of the 18.2 Hz
  timer (`setTimerAndShakeFrequency`, `ScummEngine::go`). `--run ... --wav file.wav` records a run.
- Done: saves (`Maniacal.Scumm.Saves`): ScummVM's save format for these versions, field for field
  (`ScummEngine::saveLoadWithSerializer`, `ScummEngine_v2::saveLoadWithSerializer`, the actor,
  script, object, verb, sentence and string serializers, the resources, gzip, the header and the
  information section), written in save version 108 (ScummVM 2.7's) by default or 124, and read
  from 108 to 124; the game's own save screen (`o4_saveLoadGame`), saving mid-script as ScummVM
  does and, after a load, carrying on after the instruction or booting and loading again when the
  save was made outside the save room. Checked against ScummVM 2.7.0: a save made here loads
  there; a save-screen save made here, loaded there, is saved again by ScummVM and loads back
  here; and the two saves of the same moment differ only in the mouse and a few ticks of time.
- Done: the copy protection (`GAMEOPTION_COPY_PROTECTION`): as in ScummVM, it is bypassed by
  default, `getState` keeping both sides of the steel security door (objects 182 and 193) open so
  its code is never asked for; `--copy-protection` keeps it.

## Phase 5: Commodore 64 (V0)

- Done: the disk images (`C64DiskImage`, from `ScummDiskImage`): the two disks seen as the DOS
  releases' loose files, the index rebuilt as `00.LFL` (signature `0x0132`) and each room's
  resources gathered from its track and sector into `NN.LFL`, encoded as the DOS files are, with the
  per-room resource counts and track starts generated by `tools/port_disk_tables.py`. The disks are
  found by ScummVM's names (`maniac1.d64`, `maniac2.d64`, `maniacdemo.d64`) or, failing those, by
  the words two disk images start with. The version 0 index (`readClassicIndexFile`: 256 objects,
  25 costumes, 160 scripts, 70 sounds, fewer in the demo) and detection by the MD5 of the rebuilt
  index, as `openDiskImage` does: the copy here is ScummVM's English C64 row. Checked: every room
  file is an exact chain of sized resources, and the index entries that point at real resources
  are counted and pinned, as for DOS.
- Done: rooms. The header is version 1's; objects (`ScummEngine_v0::resetRoomObject`) have their
  fields a byte earlier, the name's offset at 13 and the verbs from 14, a type in the number's high
  byte (0 for objects with an owner and state, 1 for those that are part of the room), and an
  image offset equal to the first code block's when they have none (`resetRoomObjects`). The
  walkboxes are rectangles up to an 0xFF, corner boxes narrowing their top as
  `getBoxCoordinates` has it, followed by each box's neighbours rather than a matrix
  (`getBoxConnectionBase`, `getNextBox`; the C64's own search is `walkboxes/walkbox_dfs.asm`).
- Done: pictures. `GdiV1` draws them, in the C64's own colour numbers and ScummVM's C64 palette
  (`tableC64Palette` and the rows of `setV1ColorTable`, generated with the EGA palette by
  `tools/port_palettes.py`). The layers come in another order, the mask map last. The mask
  characters' length word is 8 more than their data, as in version 1; the C64 decodes the whole
  length (`read_room_graphics` in `resources/room_loader.asm`), and its last tile is used, so
  Maniacal does too where ScummVM stops 8 bytes short. Checked: every room's picture ends where
  what follows it begins, the 250 object images that are their objects' own decode, and the front
  of the mansion and the hall look right by eye (no C64 screenshot to compare against yet).
- Done: decoding the V0 scripts: the opcode table of `ScummEngine_v0::setupOpcodes` (generated
  with version 2's by `tools/port_opcodes.py`) and the operand layout of each of its 95 handlers.
  Version 0 reads a word operand as a byte (`fetchScriptWord`, `getVarOrDirectWord`) but a jump
  as a word; the state instructions take their object as a byte, or with bit 0x40 none, meaning
  the running sentence's object (`getActiveObject`); text is bytes to a zero, bit 7 a space
  after (`decodeParseString`). Every global, room and object script of the C64 release decodes
  along every path, jumps landing on instructions, with the 20 leftover bytes of V2 script 59 after
  C64 script 54; and every instruction offset in `docs/scripts/retail` (154 global scripts, 75
  room scripts, 434 objects' scripts) is one decoded here, but for the meteor, whose Pick up
  begins with another instruction in the copy here than in the listing's.
- Done: the C64 boots to its kid selection. The engine's variables are numbered as each version
  numbers them (`EngineVariables`, from both `setupScummVars`), with none where a version has none,
  as ScummVM's `VAR_*` stay 0xFF: version 0 has nine, and keeps its lights in the engine
  (`getCurrentLights`, set by `o_lights`). Its own bit variables (`_bitVars`), the sentence's verb
  and objects the scripts read (`_cmdObject`), and the instructions the boot runs: `o_cutscene`
  and `o_endCutscene` with the mode and room they keep, `o_setMode` and the four modes as user
  states, `o_print` and `o_printEgo` with version 0's text (`decodeParseString`), and the
  resource instructions, which do nothing here. Objects that are part of a room have no state.
  `startScene` resets the sentence and runs script 5 in versions 1 and 2 only. The screen is
  `initScreens(9, 145)`, and a step 4 ticks at the C64's 240 quarter-frames a second (NTSC); the
  ticks for the C64's redraw time came later. Sounds went nowhere until the SID player was ported,
  as in ScummVM built without it.
- Done: the C64's verbs and sentences, which its engine handles itself: the 15 verbs of
  `resetVerbs` (generated by `tools/port_v0_verbs.py`) in its colours, the sentence line and
  inventory a pixel right and down; `processInput` (F1 to F3 for the kids, Escape and the right
  button always skipping a cutscene); `checkExecVerbs` making the sentence from clicks, with the
  keypad mode's Push carried out at once; `verbExec`, `drawSentenceLine` with New kid's names,
  `switchActor`, `checkAndRunSentenceScript` with its pick-up first and walk first, and
  `runSentenceScript` with Give's default and script 3 for verbs no object answers;
  `o_doSentence`. Version 0's catch-all verb entry is What is, 0x0F (`getVerbEntrypoint`), so the
  portraits' What is scripts answer the keypad's Push. Objects carry their type in their number
  (`OBJECT_V0`), and only an actor-type number is an actor (`objIsActor`). Checked: the kids are
  picked by clicking, and START starts the intro, which stops at its first costume.
- Done: the C64's costumes and actors. `V0Costume` reads the format of
  `V0CostumeLoader::loadCostume`: 8 limbs, each with sequences of cels, and clips that each start a
  sequence on every limb, mirrored or not. `V0CostumeState` plays them (`costumeDecodeData`,
  `limbFrameCheck`, `increaseAnims`, each clip with its repeats) and `V0CostumeRenderer` draws them
  as `drawLimb` does, 2-wide pixels in the actor's own colours, generated with the actors' names,
  talk colours and talk flags by `tools/port_v0_actors.py`. `ActorV0` is `Actor_v0`: clips in
  place of frames (`animateActor`, `startAnimActor`, `setDirection`, `turnToDirection` turning at
  once), 2 for standing in `_moving`, the mouth's clips (`speakCheck`, opened and shut each frame by
  `processActors`, which animates the actors before drawing them and draws the plant first), and
  its own walking: the boxes on the way planned as it sets off (`walkBoxQueuePrepare`), a point in
  each next box (`walkboxFindTarget`), and a column or line a step that goes round a box's edge
  when it must (`walkActor`, `calcWalkDistances`, `actorWalkXCalculate`, `updateWalkbox`). Points
  are moved into the boxes from box 0 up, columns counting double, and off slanted boxes' diagonals
  (`adjustPosInBorderWalkbox`). The instructions: `o_animateActor`, `o_getActorMoving`,
  `o_setActorBitVar` and `o_getActorBitVar` (a frozen kid stops), `o_putActorAtObject`,
  `o_walkActorToObject`, `o_loadRoomWithEgo` and `o_getClosestActor`; the walk before a sentence
  is `walkToActorOrObject`'s. The game starts with Dave (`resetScummVars`), and verbs are drawn a
  pixel right and down, as `drawVerb` does on the C64. `--costume N` draws the C64's costumes too.
  Checked: every clip of every costume decodes; the intro plays to the mansion's drive, where Dave
  walks where the room is clicked and reads the sign, and the screen there looks right by eye.
- Differences from ScummVM: in a slanted box, `adjustPosInBorderWalkbox` makes every column up to
  160 on the diagonal 0, where the C64 keeps it and makes only a column past 160 0
  (`clamp_to_diagonal_edge` in `walkboxes/walkbox_snap.asm`); Maniacal follows the C64. The test
  for reaching the last box (`areBoxesNeighbors`) reads the neighbour lists from 4 bytes in, as
  ScummVM does; the C64 plans its routes another way (`walkboxes/walkbox_waypoint_planner.asm`).
- Done: the C64's inventory: `o_pickupObject`, `o_setOwnerOf` and `o_setObjectName`, 0 meaning
  the running sentence's object, the name's object typed by the opcode's bit 0x80; the inventory
  is cleared a pixel right and down, as `redrawV2Inventory` does on the C64. Every version 0
  instruction now has a handler. Checked: Dave goes from the street to the porch, pulls the door
  mat, picks up the key (which the inventory shows), unlocks the front door with it, which opens
  it, and walks into the hall.
- Done: C64 saves, in ScummVM's format. Each actor saves `Actor_v0`'s fields after `Actor`'s, in
  place of version 2's step fields, and starts its clip again when loaded as
  `Actor_v0::saveLoadWithSerializer` does; the engine's mode, lights, sentence and walk follow
  version 2's fields (`ScummEngine_v0::saveLoadWithSerializer`), and a read before save version
  124 leaves room for them after the music engine's block. The bit variables, the cutscene's mode
  and room, the C64's palette and its boxes as `resetRoomSubBlocks` keeps them go in too; its actor
  names are the engine's, not resources. F5 opens the game's own save screen (script 2) and F7
  skips a cutscene (`ScummEngine_v2::processKeyboard`); a load from outside it in the save room ends
  the save screen (`ScummEngine_v0::terminateSaveMenuScript`). The cursor takes the C64's colours
  (`default_v0_cursor_colors`). A restart now puts the C64's actors back as well.
- Checked against ScummVM 2.7.0: a save made with the C64's save screen in the hall loads there
  from the launcher (its MD5 and version accepted, the save screen shown), and ScummVM writes it
  again; that save loads here into the hall with Dave where he was, and the two saves differ only
  in a script's delay and the talk delay (ScummVM saved a moment later), the mouse (ScummVM had
  none), the actors' clips (which its load starts again) and the cursor's colours, which are the
  DOS ones in 2.7.0 and the C64's in ScummVM now. The C64 was only checked through saves, which
  need no input, not by playing it there.
- Done: the C64's sound. `Sid` is ScummVM's SID emulator (`audio/softsynth/sid.cpp`, from reSID):
  three voices of a 24-bit oscillator, noise register and ADSR envelope, the combined waveforms of
  the 6581, its filter with the cutoff curve reSID's spline draws, and the C64's output stage,
  clocked at the NTSC rate and sampled; its tables come from `sid.cpp` and `wave6581.cpp` by
  `tools/port_sid_tables.py`. `PlayerSid` is `Player_SID`, ported from the C64 engine's own
  driver: songs on the three voices through the player's channel buffers, sounds that take voices,
  pulse widths and the filter by priority, a background sound stepped out of sight while it waits
  for a voice, ticked 60 times a second (`EmulatedChip::readBuffer`); its resource locking, which
  changes nothing, is left out. The players share a base (`MusicPlayer`, ScummVM's `MusicEngine`).
  Checked against ScummVM 2.7.0, recorded with SDL's disk audio driver from the same save: a sound
  came out sample for sample the same, and a later one, started at another point of the chip's
  frame, correlates at 0.998; the loudness runs alike through the intro, ScummVM's pauses longer
  by the redraw time it adds. Every one of the 66 sounds (6 songs) plays.
- Done: the time the C64 took to draw, which ScummVM adds to each step (`DelayCalculateDelta`):
  7 ticks for each object redrawn (`markObjectRectAsDirty`, from the intrinsic state changes and
  picking up) and 0.6 for each of its strips on screen, 2 for each talking mouth flipped and 0.3 for
  each actor whose limbs moved (`processActors`), 3.6 when the room is redrawn because the camera
  moved, an object changed, or the room, lights or a load call for it (`scummLoop_handleDrawing`'s
  test); rounded, and added to the next step, as `ScummEngine::go` does. ScummVM's weights were
  "based on trial/error with visual inspection against WinVice", and are the same in 2.7.0.
  Checked: the boot's first step takes 4 ticks more for the title room, steps with nothing drawn
