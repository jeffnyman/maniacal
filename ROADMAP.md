# Maniacal roadmap

What is done, what comes next, and where each piece comes from. Source references are to the
ScummVM checkout next to this repository (`scummvm/engines/scumm`); `docs/...` is the documentation
in this repository; [docs/building-an-interpreter.md](docs/building-an-interpreter.md) explains the layers below.

## Design

ScummVM builds Maniac Mansion's engine as a chain of subclasses:
`ScummEngine_v0 : v2 : v3old : v3 : v4 : v5 : ScummEngine`. Much of what Maniac Mansion runs on
lives in the V5 and base classes, mixed with code for later games (iMUSE, HE, SMUSH, AKOS,
256 colours). Maniacal does not port that chain. It has one flat `ScummEngine` with the version (0, 1
or 2) as data, and it takes from each ScummVM function only the branches that `_game.version <= 2`
and `GID_MANIAC` reach. Where V0 genuinely differs (scripts, verbs, actor walking), it gets its own
class, as Daventry did for preAGI.

The three versions split the work like this:

| | V0 (C64) | V1 (DOS 1987) | V2 (DOS 1988) |
|---|---|---|---|
| Scripts | `script_v0.cpp` | `script_v2.cpp` | `script_v2.cpp` |
| Index | inside the disk image | `readClassicIndexFile` | `readEnhancedIndexFile` |
| Room graphics | `GdiV1` (C64 character tiles) | `GdiV1` | `GdiV2` |
| Costumes | `V0CostumeLoader` / `V0CostumeRenderer` | `ClassicCostume*`, version 1 branches | `ClassicCostume*` |
| Sound | `Player_SID` | `Player_V1` (PC speaker, PCjr) | `Player_V2` (PC speaker, PCjr) |
| Verbs | V0 sentence UI (`ScummEngine_v0::checkExecVerbs`) | V2 verbs | V2 verbs |

So the order is V2 first, because ScummVM's support for it is the best exercised and it has the
fewest special cases. V1 follows by swapping in the `GdiV1` graphics and V1 costumes under the same
script VM. V0 comes last, with its own scripts and verbs, which then reuse V1's graphics.

Every phase ends with a headless check, as in Daventry: a screenshot of a known room, or a scripted
run of clicks that reaches a known state.

## Done

- Solution layout on the Daventry host packages (`Daventry.Core`, `Daventry.Audio`, `Daventry.Host.Sdl`).
- Detection: ScummVM's 40 Maniac Mansion MD5 rows (generated by `tools/port_md5_table.py`), the
  variant-to-version table of `detection_tables.h`, and identification of the loose-file releases by
  `00.LFL` / `00.MAN`. V1 and V2 English DOS are identified.
- Resources (V1 and V2): the XOR-encoded `.LFL` files (`LflFile`), both index formats
  (`ResourceIndex`: object owners and states, and where every room, costume, script and sound
  is), and loading a resource by its size word (`ResourceLoader`). Checked against both releases:
  every room file is a chain of sized resources, and the index entries that point at real resources
  are counted and pinned in the tests.

## Phase 1: resources (done)

Both DOS releases, in `Maniacal.Scumm.Resources`, `Rooms`, `Graphics` and `Costumes`:

- `file.cpp`, `resource.cpp`, `resource_v2.cpp`: the XOR-encoded LFL files, both index formats, and
  loading a resource by its size word (`ResourceLoader`).
- `room.cpp`, `object.cpp`, `boxes.cpp` (reading): the room header, the objects' code blocks
  (number, geometry, parent, walk-to point, preposition, name, verb table), the walkboxes and box
  matrix, the entry and exit scripts, and the sounds and scripts loaded with each room.
- `gfx.cpp`, `palette.cpp`: room pictures and masks (`V2Bitmap`, `V1Bitmap`), object images, and
  drawing a room with its objects as `drawRoomObjects` does (`RoomRenderer`), in EGA colours.
- `costume.cpp`: the classic costume format (`0x58`, V2) and its C64-derived variant (`0x57`, V1):
  animations, limb command runs, cels, and figures built from them (`Costume`, `CostumeRenderer`),
  with V2's start offset of (-72, -100) from `drawCostume` and V1's actor colour tables.
- No charset files: V1 and V2 fonts are built into the engine (`ScummEngine_v2::loadCharset` is a
  stub); the font is ported in Phase 2.
- `maniacal <folder> --room N [--objects none|initial|all] [--mask]` and
  `maniacal <folder> --costume N` write rooms and costume sheets as PNGs (`--zoom N` to enlarge).
- Checked: every room, object image and costume of both releases decodes; pictures match the room
  maps by eye and an independent decoder by hash; the room layouts end exactly where the next part
  begins.

## Phase 2: drawing (V2, then V1)

- Done: the V2 picture and mask decoder (`GdiV2::prepareDrawBitmap`, `generateStripTable`) as
  `V2Bitmap`, and the EGA palette. Every V2 room decodes, ending exactly where its object images begin.
- Done: the V1 tile decoder (`GdiV1::roomChanged`, `decodeV1Gfx`, `drawStripV1Background`,
  `drawStripV1Mask`) as `V1Bitmap`, with the Maniac Mansion EGA row of `setV1ColorTable`. Every V1
  room decodes, ending exactly where its object images begin.
- The CGA and Hercules colour maps of `setV1ColorTable` and `resetPalette`, if wanted.
- `palette.cpp`: done for DOS; V1 and V2 both use the EGA palette (`resetPalette`). The C64 palette
  comes with V0.
- Done: actors on the room (`RoomView`): the position offsets of `Actor_v2::prepareDrawActorCostume`
  (+8 in V2, +16 facing left), V1's one-line drop, and clipping by the room mask when the actor's
  walkbox has one (ScummVM's two mask planes: plane 0 empty, plane 1 the room's). Still to do: the
  dark-room colours of `setPalette`, and sorting actors by depth (with the walking code).
- Done: the built-in English font (`CharsetRendererV2`, `charset-fontdata.cpp`, generated by
  `tools/port_fonts.py`), with V1's own apostrophe, and drawing text with it (`Font`). Other languages'
  replacement glyphs can be ported the same way when there is data to test them.
- Done: `camera.cpp` (`Camera`): the view centre in pixels, 8 pixels a step, following an actor past
  view columns 10 and 30, panning, and the script limits that `startScene` resets on each room.
- Done: the screen layout of `initScreens` (`ScreenLayout`), and
  `maniacal <folder> --view N [--camera X] [--actor costume,x,y[,direction]]...`, which writes the
  320x200 screen with the room and standing actors.
- `gfx.cpp`: drawing into a 320x200 frame each step with dirty strips, for the engine loop.
- Check: headless screenshots of rooms with actors in them, matching ScummVM's output.

## Phase 3: the interpreter (V2 and V1)

- Done: decoding (`Maniacal.Scumm.Scripts`): the opcode table of `ScummEngine_v2::setupOpcodes`
  (generated by `tools/port_opcodes.py`) and the operand layout of each of its 107 handlers
  (`ScriptDecoder`), with decoding along every path execution can take. Every global, room and
  object script of both releases decodes, with jumps landing on instruction boundaries; the only
  leftover bytes are 20 after V2 script 59. `maniacal <folder> --script N` and `--room-scripts N`
  print the disassembly.
- Done: the script engine core (`ScriptEngine`): 80 slots, nested starts, `runAllScripts`, delays,
  freezing, the user state, cutscenes and overrides, variables (with the 14-16 redirection and the
  exit-key remap), bit variables, object states and owners, and the variable, arithmetic,
  condition, jump and script-control instructions. Every other instruction goes to an
  `IScriptHost` with its operands evaluated. `maniacal <folder> --run [steps]` runs the boot script
  headless and lists what the scripts asked of the world: both releases reach the kid selection.
- Done: the first world host (`GameWorld`): `loadRoom` as `startScene` does it for these versions
  (leave and kill the room's scripts, the exit script, the room variable, the camera limits, the entry
  script, then script 5), `setCameraAt`, `panCameraTo`, the camera limits of `roomOps`, and `lights`;
  a main-loop step (delays, scripts, camera); and the screen drawn from the object states.
  `maniacal <folder> --run [steps] --screenshot file.png` shows the title screen in both releases.
- Done: actors without walking (`Actor`, `CostumeState`): the per-limb costume state of
  `costumeDecodeData` and `increaseAnim`; `putActor`, `showActor`, `hideActor`, `setActorCostume`,
  `animateActor`, `setDirection` and `animateCostume`; V1's default costumes and talk colours;
  `actorOps`, the put and query instructions, `actorFollowCamera` and `loadRoomWithEgo`; drawing
  the actors in the room back to front, in their palette under the current lights. With the kid
  selection stood in for by `--set` and the intro skipped by `--skip`, both releases reach the start
  of the game with the three kids on the driveway.
- Done: walking (`BoxGeometry`, `Actor`): the box geometry of `boxes.cpp`, V2's
  `adjustXYToBeInBox` and `adjustActorPos`, `startWalkActor`, `walkActor` leg by leg through the box
  matrix, `calcMovementFactor` and `actorWalkStep`, turning a quarter at a time
  (`updateActorDirection`, `remapDirection`), and the box flags `setBoxFlags` changes. The walk,
  face, wait and distance instructions; `drawObject` without moving; and the per-step engine
  variables of `scummLoop_updateScummVars` (the camera column). The intro plays through in both
  releases, from the meteor to the kids on the driveway.
- Next: verbs, the sentence and input, so the game can be played: the verb area, the inventory,
  clicking (`checkExecVerbs`, the sentence script), and the text of `print` with the message line.
- Then: objects (`drawObject` positions, pick up), `getClosestObjActor` and `actorFromPos`, sound,
  and dark rooms.
- `script.cpp`: script slots, `runScript`, `runObjectScript`, `runEntryScript`/`runExitScript`,
  cutscenes, `stopScript`, freeze and unfreeze, the bit variables.
- `script_v2.cpp`: the V2 opcode table (also used by V1) and every handler.
- `vars.cpp`: `ScummEngine_v2::setupScummVars` and `resetScummVars`.
- `scumm.cpp`: the main loop (`scummLoop` and what it calls each frame), `resetScumm`, timing.
- `actor.cpp`: `Actor`, `Actor_v3` and `Actor_v2`, with walking, facing, animation and talking.
- `boxes.cpp`: walkboxes, the box matrix and path finding, version 2 branches.
- `verbs.cpp`: `initV2MouseOver`, `checkV2MouseOver`, `redrawV2Inventory`, `checkExecVerbs`.
- `string.cpp`: messages, `drawSentence`, talk text.
- `input.cpp`: mouse and keyboard, `ScummEngine_v2::processKeyboard`.
- Cross-check script behaviour against `docs/scripts`. Those are the C64 scripts: the logic is
  the same game, but DOS renumbers scripts, variables and objects (see
  `docs/scripts/README.md`, "The DOS releases"), so build a V0-to-DOS number map before naming
  variables from the tables in debug output.
- Check: from the title, through the intro and kid selection, to walking around the front of the
  house, headless and in the SDL window.

## Phase 4: sound, saves and options (V2 and V1)

- `players/player_v2base.cpp`, `player_v2.cpp`: V2 PC speaker and PCjr music and effects.
- `players/player_v1.cpp`: V1 PC speaker and PCjr.
- `sound.cpp`: the sound queue as far as V1/V2 use it.
- `saveload.cpp`: ScummVM's save format for these versions (`ScummEngine_v2::saveLoadWithSerializer`
  and the base serializer), so saves can be swapped with a real ScummVM build as Daventry's are.
- The copy-protection door code (`GAMEOPTION_COPY_PROTECTION`): ScummVM bypasses it by default.
- Check: a WAV capture of the title music; saves made here load in ScummVM and back.

## Phase 5: Commodore 64 (V0)

- `file.cpp`: `ScummDiskImage`, reading `maniac1.d64`/`maniac2.d64`, and C64 detection
  (ScummVM hashes the index it pulls out of the disk image, not the `.d64` itself).
- `script_v0.cpp`, `scumm_v0.h`: the V0 opcode table, sentence queue and verb handling.
- `verbs.cpp` / `input.cpp` / `object.cpp`: the `ScummEngine_v0` overrides.
- `actor.cpp`: `Actor_v0`, which walks differently (walkbox traversal and path DDA).
- `costume.cpp`: `V0CostumeLoader` and `V0CostumeRenderer`.
- `players/player_sid.cpp`: the SID player. Daventry has no SID emulation, so this is new code.
- `docs/c64-engine` is the authority here: `interpreter/script_engine.asm`, `include/opcode_handlers.inc`,
  `walkboxes/`, `ui/sentence_action.asm`, `sound/sid_voice_controller.asm`.
- Check: the C64 release plays from its own disk images, checked against the commented engine.
